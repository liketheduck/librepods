# AOSP Patch: Fix L2CAP FCR Mode Negotiation (Bug 371713238)

This directory contains patches to fix the long-standing Android Bluetooth bug that prevents L2CAP connections to devices using Basic mode (like Apple AirPods).

## The Problem

Android's Bluetooth stack incorrectly rejects L2CAP connections when the peer device (like AirPods) only supports Basic L2CAP mode. The error message is:

```
l2c_fcr_chk_chan_modes: L2CAP - Peer does not support our desired channel types
```

This affects:
- AirPods (all models) using PSM 0x1001
- Other Bluetooth devices using Basic L2CAP mode
- Any app trying to use `BluetoothDevice.createL2capChannel()` or `createInsecureL2capChannel()` with these devices

**Google Issue Tracker**: https://issuetracker.google.com/issues/371713238

## The Fix

Two patches are provided:

### Patch 1: `0001-Bluetooth-Fix-L2CAP-FCR-mode-negotiation.patch`
Modifies `l2c_fcr_chk_chan_modes()` to accept Basic mode connections:
- When peer requests Basic mode, accept it
- When FCR option is not present (implies Basic mode per spec), accept it
- Maintains compatibility with ERTM/Streaming mode peers

### Patch 2: `0002-Bluetooth-Skip-extended-features-for-Basic-mode.patch`
Optimizes connection flow for Basic mode:
- Skips unnecessary Extended Features info request for Basic mode connections
- Prevents timeouts caused by some devices not handling this request

## Technical Background

### L2CAP FCR Modes (Bluetooth Core Spec)

| Mode | Value | Description |
|------|-------|-------------|
| Basic | 0x00 | Simple mode, no flow control/retransmission |
| ERTM | 0x03 | Enhanced Retransmission Mode |
| Streaming | 0x04 | Streaming Mode |

**Basic mode is ALWAYS valid per Bluetooth Core Spec.** Android's implementation incorrectly assumes ERTM is required.

### Why AirPods Use Basic Mode

Apple's AirPods Audio Protocol (AAP) runs on L2CAP PSM 0x1001 using Basic mode because:
1. Audio data is time-sensitive; retransmission adds latency
2. The protocol handles its own reliability at the application layer
3. Basic mode has lower overhead

### Current Android Behavior (Broken)

```
1. App calls createInsecureL2capChannel(0x1001)
2. Android sends L2CAP Connection Request
3. AirPods respond with Configuration Request (Basic mode)
4. l2c_fcr_chk_chan_modes() checks modes
5. Returns FALSE because peer_mode (Basic) != our_mode (ERTM)
6. Connection dropped
```

### Fixed Behavior

```
1. App calls createInsecureL2capChannel(0x1001)
2. Android sends L2CAP Connection Request
3. AirPods respond with Configuration Request (Basic mode)
4. l2c_fcr_chk_chan_modes() checks modes
5. Sees peer wants Basic mode, sets our_mode = Basic
6. Returns TRUE
7. Connection succeeds!
```

## How to Submit to AOSP

### Prerequisites

1. **Sign the Google CLA**
   - Go to https://cla.developers.google.com/
   - Sign as individual or corporate contributor

2. **Set up Gerrit account**
   - Visit https://android-review.googlesource.com
   - Sign in with your Google account
   - Generate HTTP password in Settings

3. **Configure Git**
   ```bash
   git config --global user.email "your-email@example.com"
   git config --global user.name "Your Name"
   ```

### Submission Steps

```bash
# 1. Initialize repo with AOSP manifest
mkdir aosp && cd aosp
repo init -u https://android.googlesource.com/platform/manifest -b android-latest-release
repo sync packages/modules/Bluetooth

# 2. Navigate to Bluetooth module
cd packages/modules/Bluetooth

# 3. Create a new branch
repo start fix-l2cap-fcr-371713238 .

# 4. Apply the patches
git am /path/to/0001-Bluetooth-Fix-L2CAP-FCR-mode-negotiation.patch
git am /path/to/0002-Bluetooth-Skip-extended-features-for-Basic-mode.patch

# 5. Build and test (requires full AOSP build environment)
m libbluetooth

# 6. Upload to Gerrit
repo upload .
```

### Commit Message Format

The commit messages in the patches follow AOSP guidelines:
- Subject line under 50 characters
- Body wrapped at 72 characters
- `Bug:` line references the issue
- `Test:` lines describe testing performed
- `Change-Id:` will be auto-generated by Gerrit hooks

### Review Process

1. Upload creates a Gerrit change
2. Add reviewers from the Bluetooth team:
   - Search for recent Bluetooth commits to find active reviewers
3. Address any review feedback
4. Once approved, Google will merge

## Testing

To verify the fix works:

1. Build AOSP with patches applied
2. Flash to a test device
3. Install an app that uses L2CAP (like OpenPods)
4. Connect to AirPods
5. Verify L2CAP connection succeeds on PSM 0x1001

### Test Commands

```bash
# Enable Bluetooth HCI logging
adb shell settings put global bluetooth_hci_log 1

# Check logcat for L2CAP messages
adb logcat | grep -i "l2cap\|l2c_fcr"

# Should see:
# "L2CAP - Peer requests Basic mode, accepting connection"

```
